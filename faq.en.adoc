[[faq]]
== FAQ

*Q. What is the state of the MDT?*  

*A.* The MDTs are part of a pilot phase of the GBIF Metabarcoding Data Programme. The MDTs can be used for data processing and publishing by anybody. GBIF nodes who wish to administer an instance of the MDT can apply for a GBIF hosted MDT.

*Q. Where can bugs and errors be reported?*  

*A.* Please make a GitHub issue https://github.com/gbif/metabarcoding-data-toolkit-ui/issues[here].

*Q. What does the MDT do?*

*A.* The MDT reshapes and formats a DNA metabarcoding dataset for publication on GBIF.org – transforming the familiar broad OTU table (with associated sample info & taxonomic/sequence information) into a DarwinCore Archive. These are in principle formatting steps that can be done manually following the guidelines in the guide https://doi.org/10.35035/doc-vf1a-nr22[Publishing DNA-derived data through biodiversity data platforms], but the MDT automates this and makes it easier.

*Q. What kind of data can be published using the MDT?*

*A.* DNA metabarcoding dataset in the shape of an OTU table, i.e. a table of amplified sequences (ASVs/OTUs) and their abundance across a set of samples, with each sample corresponding to e.g. environmental or bulk sample (air, soil, water, faeces, insect trap homogenate, gut contents, ...).

*Q. Can the MDT be used for metagenomic datasets?*

*A.* No. BUT: There is often confusion between the terms 'metagenomic' and 'metabarcoding.' Here we define *metagenomics* as involving sequencing of all genetic material in an environmental sample, typically using shotgun sequencing _without_ a PCR step to target specific genetic (barcode) regions. In contrast, *metabarcoding* involves PCR amplification of specific DNA regions (e.g., CO1, ITS, 18S, 16S), often referred to as barcoding regions. Thus, "16S amplicon" data – although often referred to as "metagenomics" in some communities – is metabarcoding data and can be processed in the MDT. 

*Q. Which sample types are acceptable to publish on GBIF.org?*

*A.* All environmental samples (soil, air, water, dust, etc) and bulk samples (e.g. malaise traps) and gut contents are acceptable. Heavily manipulated/treated environmental samples may not reflect "real biodiversity" and be relevant from a general biodiversity perspective. Use your knowledge and critical judgment.

*Q. Which markers/barcodes (COI, ITS, 16S,..) does GBIF and the MDT support?*

*A.* It is possible to publish data from any barcoding gene/region. 

*Q. Should sequences be trimmed?*

*A.* Primers, adapters, tags, etc. should always be removed from sequences, as these do not represent real biology. Further trimming – of e.g. the remnants/ends of 5.8S and 28S from ITS2 data – is optional.

*Q. Should sequences be clustered into OTUs?*

*A.* Some compression of data is needed. 100% identical sequences should always be collapsed (dereplicated), and shorter 100% identical sequences should preferably also be merged with their identical, longer counterparts. Additional clustering, denoising and compression may be relevant depending on sequencing platform and bioinformatic tools used. Unclustered amplicon sequence variants (ASVs) – e.g. Illumina sequences processed with the dada2 – is compatible/interoperable with data from similar studies, whereas clustering into broader (e.g. 97% similarity) OTUs may result in incompatible picking of representative sequences of similar OTUs.

*Q. Should sequence read abundance be converted to relative abundance?*

*A.* No. It is best practice to share absolute sequence read abundance (detected number of reads of each ASV/OTU in each sample). The MDT calculates the total number of reads per sample, relative abundance is calculated when indexing in GBIF, and users are able to filter on absolute and relative abundance.

*Q. Should samples be resampled/rarefied to even sequencing depth?*

*A.* No. MDT/GBIF calculates total number of reads per sample and relative abundances, and users can filter on both absolute and relative abundances. Resampling/rarefaction makes sense across a set of samples when analysing them together, but it is a lossy process, and it is recommended to share the more intact data, as users may do the resampling themselves on a set of downloaded samples. 

*Q. Should negative controls, positive controls, blanks and failed samples be removed from the dataset?*

*A.* Yes. Only real biological/environmental samples should be shared. Control samples can be excluded from the final data by excluding them in either the sample table or the OTU table.

*Q. Should singletons, infrequent and low abundant sequences be removed?*

*A.* No, not necessarily. Consider removing them if they seem like contamination or are otherwise untrustworthy.

*Q. Should data from replicates be merged?*

*A.* Maybe. Do what makes the data most suitable for reuse in biodiversity studies. If replication (multiple samples, DNA extractions, PCRs) was used to reduce stochasticity, merging replicates may be a good choice.

*Q. What if there are several versions of an OTU table?*

*A.* Only one verison of the OTU table should be shared. Sometimes several version of an OTU table exist - e.g. tables clustered at different thresholds, tables with non-target species removed, tables with different taxonomic scopes, etc. Share the most relevant version seen from a biodiversity perspective. 

*Q. Should data from suspected contaminants be removed?*

*A.* Yes. Some sequences/OTUs may be suspected contamination (e.g. DNA from humans, pets, classical food items like tomato, potato, chicken, etc.). We recommend to remove these if they can be identified. Excluding suspected contaminants can be done by deleting those from the *Taxon* table.

*Q. Should non-target sequences be removed?*

*A.* Not necessarily. Some sequences/OTUs perceived as non-target - e.g. if mammals detected in a study using fish-specific primers. However, non-target sequences may still be relevant in a broader perspective. Also, such custom filterings of data may actually make the data less compatible/interoperable with similar datasets produced with the same primers, and it makes the automatic calculation of relative read abundances flawed. Consider removing non-target sequences if they are obvious contamination or otherwise untrustworthy.

*Q. Should taxonomy be assigned to sequences?*

*A.* Not necessarily. GBIF index data based on the taxonomy you provide. If an OTU is shared as a sequence without taxonomy, it will be indexed as "_incertae sedis_" (uncertain placement). However, the sequence will be possible to identify taxonomically at a later stage.

*Q. How should taxonomy be assigned to sequences?*

*A.* GBIF does not recommend any particular reference databases or tools. There are many DNA reference databases (BOLD, MIDORI, UNITE, MiFish, etc.) and tools (RDP Classifier, BLAST, VSEARCH, mothur, etc.) for assigning taxonomy to sequences, and reference databases are continuously being improved and changed. Use what is appropriate for the data. GBIF.org offers the https://www.gbif.org/tools/sequence-id[Sequence ID] tool (GBIF.org > TOOLS > Sequence ID) for some of the frequently used markers and databases. You can use that if you wish. This tool is  built into the MDT as an option during the processing step, but as this step takes time you may want to use the sequence ID tool at an earlier step as part of the dataset preparation.

*Q. Should I share sequences that cannot be taxonomically identified?*

*A.* Yes. All OTUs/ASVs should be shared. Sequences that cannot be reliably identified to species level (or to genus, or any taxonomic level at all) generally reflect the fact that DNA reference databases are incomplete. However, reference databases are continuously improved, and many currently un-identifiable sequences will be possible to identify in the future. So please provide all OTUs/sequences.

*Q. Will GBIF make sure that the taxonomy is updated?*

*A.* This is an often heard question from DNA data publishers and users. For many barcoding regions and taxonomic groups, reference databases are incomplete and partially incorrect. However, reference databases are continuously improved, and many currently un-identifiable sequences will be possible to identify in the future. Whether GBIF will provide such service is currently not known.

*Q. How does GBIF ensure fitness for reuse and interoperability of data?*

*A.* GBIF is working on generally improving the support for DNA derived data with relation to indexing, searching and filtering.

*Q. Can the MDT be used solely to create a Darwin Core Archive?*

*A.* Yes. The Darwin Core Archive can then be downloaded at the 6th processing step *Export*. It can then be published to GBIF, OBIS or another research infrastructure through any standard publishing procedure.

*Q. Can the MDT be used solely to create BIOM files?*

*A.* Yes. the MDT can be used to construct a standardized BIOM file of the uploaded data. The BIOM files can be downloaded at the 3rd processing step *Process data* and at the 6th step *Export*.

*Q. Should/can data from several primers/markers be combined in one table?*

*A.* We highly recommend not to. DNA from the same set of samples may have been amplified and sequenced with several different primer sets (e.g. COI, ITS, 16S). These should be treated as different datasets (one dataset per marker / primer-set), and each dataset should be published separately. This makes the data maximally interoperable and reusable from a technical perspective. It also makes it possible to calculate total and relative read abundance per sample and OTU. The same sample information table file can be (re-)used for datasets relating to the same set of samples. NB: If you want to use the MDT to convert a table where data from different markers have been merged/mixed, you will need to supply the corresponding primer information etc for every single entry (OTU/ASV) in the taxon table, but the calculations of relative read abundances will be erroneous and misleading.
